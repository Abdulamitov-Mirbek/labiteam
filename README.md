# ТЗ 6. OTP-сервис

REST API выдачи и проверки одноразовых кодов с защитой от перебора и спама запросами.
FastAPI + Redis (вся логика лимитов — атомарные Lua-скрипты).

## Запуск

```bash
docker compose up --build
```

Сервис: <http://localhost:8000>, дашборд событий безопасности: <http://localhost:8000/dashboard>.

Код «отправляется» в консоль сервиса строкой вида:

```
[SMS] на 996700111222: ваш код 042917 (действует 120 с)
```

```bash
docker compose logs -f api | grep SMS     # смотреть отправленные коды
```

Без Docker (хранилище в памяти процесса, Redis не нужен):

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000 --no-proxy-headers
```

## API

| Запрос | Ответ |
|---|---|
| `POST /otp/send {"msisdn"}` | `200` — код выдан; `429` — лимит (заголовок `Retry-After`) |
| `POST /otp/verify {"msisdn", "code"}` | `200` — верно; `401` — неверный код; `410` — код истёк, использован или не выдавался; `423` — номер заблокирован; `429` — лимит проверок с IP |
| `GET /dashboard` | дашборд событий безопасности |
| `GET /admin/events?limit=200` | те же события в JSON |
| `GET /health` | состояние и тип хранилища |

```bash
curl -X POST localhost:8000/otp/send   -H 'Content-Type: application/json' -d '{"msisdn":"996700111222"}'
curl -X POST localhost:8000/otp/verify -H 'Content-Type: application/json' -d '{"msisdn":"996700111222","code":"042917"}'
```

Номер принимается в виде `996700111222`, `+996700111222`, `+996 700 111-222` (7–15 цифр), иначе `422`.

## Как выполнены требования

1. **Код** — 6 цифр из `secrets.randbelow`, срок жизни 120 с, одноразовый (удаляется при успешной
   проверке). Новая выдача перезаписывает запись — предыдущий код аннулируется.
2. **Хранение** — только `HMAC-SHA256(секрет, "номер:код")`; сам код нигде не сохраняется.
   Сравнение за постоянное время: `hmac.compare_digest` (хранилище в памяти) и побайтовый XOR
   без раннего выхода внутри Lua-скрипта (Redis).
3. **Отправка** — прогрессивная задержка 30 → 60 → 120 с и не больше 3 выдач на номер
   за 10 минут (скользящее окно). Отклонённый запрос действующий код не трогает.
4. **Перебор** — после 5 неверных вводов номер блокируется на 15 минут (5-й неверный ввод
   получает `401`, все следующие — `423`, даже с верным кодом). Счётчик ошибок не сбрасывается
   новой выдачей кода, только успешной проверкой. С одного IP — не больше 20 проверок в минуту
   по всем номерам (скользящее окно), дальше `429`.
5. **Параллельные запросы** — проверка и удаление кода выполняются одним атомарным шагом
   (Lua-скрипт в Redis), поэтому из параллельных `verify` с верным кодом успешен ровно один,
   остальные получают `410`. Так же атомарно считаются ошибки: 50 параллельных неверных
   вводов дают ровно 5 сверок.
6. **Журнал безопасности** — JSON-строки в stdout и в Redis (последние 1000): `otp_issued`,
   `verify_success`, `verify_failed`, `verify_no_active_code`, `msisdn_blocked`,
   `verify_while_blocked`, `send_rate_limited`, `ip_rate_limited`. Ни выданные, ни введённые
   коды в журнал не попадают.
7. **`attack.py`** — см. ниже.

IP клиента берётся только из TCP-соединения: `X-Forwarded-For` и подобные заголовки
игнорируются (`--no-proxy-headers`), обойти лимит по IP подменой заголовка нельзя.

Бонусы: хранение в Redis с TTL на всех ключах, дашборд, запуск одной командой через Docker Compose.

## Атака

```bash
python attack.py                 # обе атаки по 1000 попыток, между ними пауза 61 с
python attack.py --pause 0       # без паузы
```

1. Перебор кода одного номера (1000 разных кодов в 20 потоков).
2. Распределённый перебор по 50 номерам с одного IP.

Пауза нужна, чтобы окно лимита по IP обнулилось и вторая атака проверяла защиту с чистого
листа. Скрипт печатает распределение ответов и завершается с кодом `0`, если ни один код не
угадан. Из 1000 попыток до сверки с кодом доходит не больше 5 (атака 1) и 20 (атака 2).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest                                                   # хранилище в памяти
TEST_REDIS_URL=redis://127.0.0.1:6399/0 pytest           # + Redis (база будет очищена!)
```

Время в тестах подменяется, поэтому сценарии на 120 с / 10 мин / 15 мин проходят мгновенно.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `REDIS_URL` | — | адрес Redis; если пусто — хранилище в памяти |
| `OTP_SECRET` | случайный при старте | ключ HMAC |
| `ADMIN_TOKEN` | — | если задан, дашборд и `/admin/events` требуют `?token=` или `X-Admin-Token` |
| `OTP_CODE_TTL` | `120` | срок жизни кода, с |
| `OTP_SEND_DELAYS` | `30,60,120` | задержки повторной отправки, с |
| `OTP_SEND_LIMIT` / `OTP_SEND_WINDOW` | `3` / `600` | выдач на номер за окно, с |
| `OTP_MAX_FAILURES` / `OTP_BLOCK_TTL` | `5` / `900` | порог ошибок и срок блокировки, с |
| `OTP_IP_LIMIT` / `OTP_IP_WINDOW` | `20` / `60` | проверок с IP за окно, с |
