# ТЗ 6. OTP-сервис

REST API выдачи и проверки одноразовых кодов с защитой от перебора и спама запросами.
FastAPI + Redis (вся логика лимитов — атомарные Lua-скрипты). Поведение соответствует
`CLARIFICATIONS_RU.md`, раздел 6.

## Запуск

```bash
docker compose up --build
```

Сервис: <http://localhost:8000>, дашборд событий безопасности: <http://localhost:8000/dashboard>.

Без Docker (хранилище в памяти процесса, Redis не нужен):

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000 --no-proxy-headers
```

## Доставка кода

Каждая выдача дописывается одной строкой JSON в `outbox/sms.jsonl` в корне репозитория
(путь меняется переменной `OTP_OUTBOX`):

```json
{"ts": "2026-11-21T09:00:00+06:00", "msisdn": "996770730000", "code": "012345"}
```

Это имитация SMS-шлюза: сервис файл только дополняет и никогда не читает. Код не попадает
ни в ответ API, ни в консоль, ни в журнал безопасности, ни в Redis. HTTP-метода получения
кода нет. В Docker Compose каталог `./outbox` смонтирован в контейнер.

## API

| Запрос | Ответ |
|---|---|
| `POST /otp/send {"msisdn"}` | `200` — код выдан; `400` — неверный формат; `423` — номер заблокирован; `429` — задержка или лимит выдач (`Retry-After`) |
| `POST /otp/verify {"msisdn", "code"}` | `200` — верно; `400` — неверный формат; `401` — неверный код, кода нет или он уже использован; `410` — код истёк неиспользованным; `423` — номер заблокирован; `429` — лимит проверок с IP |
| `GET /dashboard` | дашборд событий безопасности |
| `GET /admin/events?limit=200` | те же события в JSON |
| `GET /health` | состояние и тип хранилища |

`msisdn` — строка из 12 цифр, начинается с `996`. `code` — строка ровно из 6 цифр
(ведущие нули значимы, `000000` допустим).

```bash
curl -X POST localhost:8000/otp/send   -H 'Content-Type: application/json' -d '{"msisdn":"996770730000"}'
tail -1 outbox/sms.jsonl
curl -X POST localhost:8000/otp/verify -H 'Content-Type: application/json' -d '{"msisdn":"996770730000","code":"012345"}'
```

## Как выполнены требования

1. **Код** — 6 цифр из `secrets.randbelow`, срок жизни 120 с (при `elapsed >= 120` — `410`),
   одноразовый: удаляется при успешной проверке. Новая выдача перезаписывает запись —
   предыдущий код аннулируется.
2. **Хранение** — только `HMAC-SHA256(секрет, "номер:код")`. Сравнение за постоянное время:
   `hmac.compare_digest` (хранилище в памяти) и побайтовый XOR без раннего выхода внутри
   Lua-скрипта (Redis).
3. **Отправка** — выдачи в скользящем окне `(t−600, t]` нумеруются 1, 2, 3: между первой и
   второй 30 с, между второй и третьей 60 с, после третьей 120 с, и не больше 3 выдач в окне.
   Отклонённый запрос действующий код не трогает. Когда окно очищается, ступень сбрасывается.
4. **Перебор** — пятый неверный код блокирует номер на 15 минут `[t, t+900)`, и этот же
   пятый ответ уже `423`. В блокировке `423` получают и верный код, и `send`. Счётчик ошибок
   растёт только от неверного кода при действующем OTP (ошибка формата, отсутствующий или
   истёкший код его не трогают), сбрасывается успешной проверкой и **не** сбрасывается новой
   выдачей. С одного IP — 20 проверок в окне `(t−60, t]`, 21-я — `429`. Лимит по IP
   проверяется первым и учитывает любой `verify`, в том числе с ошибкой формата.
5. **Параллельные запросы** — проверка и погашение кода выполняются одним атомарным шагом
   (Lua-скрипт в Redis): из 20 параллельных `verify` с верным кодом ровно один получает
   `200`, остальные — `401`. Ошибки считаются так же атомарно.
6. **Журнал безопасности** — JSON-строки в stdout и в Redis (последние 1000): `otp_issued`,
   `verify_success`, `verify_failed`, `verify_no_active_code`, `verify_expired`,
   `verify_bad_format`, `msisdn_blocked`, `verify_while_blocked`, `send_while_blocked`,
   `send_rate_limited`, `ip_rate_limited`, `delivery_failed`. Ни выданные, ни введённые коды
   в журнал не попадают.
7. **`attack.py`** — см. ниже.

**IP клиента** берётся из TCP-соединения. `X-Forwarded-For` учитывается, только если
соединение пришло с адреса из `OTP_TRUSTED_PROXIES` (по умолчанию список пуст, uvicorn
запущен с `--no-proxy-headers`), поэтому обойти лимит подменой заголовка нельзя.

**Отказы.** Если Redis недоступен или код не удалось записать в outbox, сервис отвечает
`503` и коды не выдаёт и не принимает.

Бонусы: хранение в Redis с TTL на всех ключах, дашборд, запуск одной командой.

## Сценарии жюри

`data/06_otp/` — открытые данные организаторов. Прогон сценариев в их формате:

```bash
pip install -r requirements-dev.txt
python scenarios.py                         # 5 открытых сценариев
python scenarios.py путь/к/scenarios.json   # любой файл того же формата
```

Каждый сценарий идёт на свежем экземпляре сервиса внутри процесса: `advance` мгновенно
сдвигает подменённые часы, `client_ip` задаётся как адрес соединения, `capture_delivery`
читает последнюю строку outbox для номера.

Для прогона по HTTP с разными `client_ip` запустите сервис с
`OTP_TRUSTED_PROXIES=<адрес стенда>` и передавайте IP в `X-Forwarded-For`.

## Атака

```bash
python attack.py                 # обе атаки по 1000 попыток, между ними пауза 61 с
python attack.py --pause 0       # без паузы
```

1. Перебор кода одного номера (1000 разных кодов в 20 потоков).
2. Распределённый перебор по 50 номерам с одного IP.

Пауза нужна, чтобы окно лимита по IP обнулилось и вторая атака проверяла защиту с чистого
листа. Скрипт печатает распределение ответов и завершается с кодом `0`, если ни один код
не угадан. Запускайте его только против своего стенда.

## Тесты

```bash
pytest                                                   # хранилище в памяти
TEST_REDIS_URL=redis://127.0.0.1:6399/0 pytest           # + Redis (база будет очищена!)
```

Время в тестах подменяется, поэтому сценарии на 120 с / 10 мин / 15 мин проходят мгновенно.

## Структура

| Файл | Назначение |
|---|---|
| `app/main.py` | HTTP-маршруты, разбор запросов, журнал событий |
| `app/store.py` | вся логика лимитов: `RedisStore` (Lua) и `MemoryStore` |
| `app/delivery.py` | запись выдач в outbox |
| `app/config.py` | настройки из переменных окружения |
| `app/dashboard.html` | дашборд |
| `scenarios.py` | прогон сценариев жюри |
| `attack.py` | имитация атак |

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `REDIS_URL` | — | адрес Redis; если пусто — хранилище в памяти |
| `OTP_SECRET` | случайный при старте | ключ HMAC |
| `OTP_OUTBOX` | `outbox/sms.jsonl` | файл доставки кодов |
| `OTP_TRUSTED_PROXIES` | — | адреса/подсети, от которых принимается `X-Forwarded-For` |
| `ADMIN_TOKEN` | — | если задан, дашборд и `/admin/events` требуют `?token=` или `X-Admin-Token` |
| `OTP_CODE_TTL` | `120` | срок жизни кода, с |
| `OTP_SEND_DELAYS` | `30,60,120` | задержки повторной отправки, с |
| `OTP_SEND_LIMIT` / `OTP_SEND_WINDOW` | `3` / `600` | выдач на номер за окно, с |
| `OTP_MAX_FAILURES` / `OTP_BLOCK_TTL` | `5` / `900` | порог ошибок и срок блокировки, с |
| `OTP_IP_LIMIT` / `OTP_IP_WINDOW` | `20` / `60` | проверок с IP за окно, с |
