# AGENTS.md — прочитать до того, как менять код

Проект «Tolkun» (ТЗ 7, карта покрытия Бишкека). Этот файл для AI-агентов и разработчиков
команды: что сделать перед работой, что недавно поменялось и чего нельзя ломать.
Подробное описание проекта — в [README.md](README.md).

## 1. Перед началом работы (каждый раз)

```powershell
git pull origin main
python -m venv .venv                                  # один раз, если папки .venv ещё нет
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q               # должно быть: 184 passed
node --test "extension/tests/*.test.js"               # должно быть: pass 7, fail 0
node --test e2e/mobile.e2e.mjs                         # мобильная версия в Chrome: pass 17, fail 0
```

На macOS/Linux: `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

- **Ставьте пакеты только в `.venv`, не в системный Python.** `pip install -r requirements.txt`
  в системный Python обновил там pydantic до 2.14 и сломал другой проект (aiogram требует
  pydantic < 2.13). `.venv` уже в `.gitignore`.
- **В `requirements.txt` появился `httpx`** — после `git pull` переустановите зависимости.
- **Плагин поменялся** — в `chrome://extensions` нажмите ↻ у «Tolkun», иначе Chrome работает
  со старым кодом.
- **Автотест мобильной версии** (`e2e/mobile.e2e.mjs`) сам поднимает сервер на свободном порту с
  временными данными и открывает `/app/` в Chrome без окна с экраном телефона: карта и квартиры,
  GPS, жалоба, очередь без сети, демо, установка, ширина 360/390/430 px, ошибки в консоли.
  Нужен Chrome (путь — переменная `CHROME`, если не найден сам). Скриншоты: `E2E_SHOTS=<папка>`.
- Если тесты красные до ваших изменений — сначала разберитесь с этим, не пишите код поверх.

## 2. Как запускать

| Что | Команда |
|---|---|
| Ядро (ответ жюри, `out/`) | `.\.venv\Scripts\python.exe main.py` |
| Сервер: панель, API, приложение | `.\.venv\Scripts\python.exe -m server --host 0.0.0.0` → <http://127.0.0.1:8000/> |
| Документация API | <http://127.0.0.1:8000/api/docs> |
| Ссылка для телефона (HTTPS) | `cloudflared tunnel --url http://127.0.0.1:8000` → `https://….trycloudflare.com/app/` |

- **Порт 8000 занят** (`Errno 10048`) — значит, сервер уже запущен в другом окне. Найти процесс:
  `Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess`.
  Плагин ходит именно на `127.0.0.1:8000` (`extension/background.js`), другой порт ему не подойдёт.
- **Телефону нужен HTTPS.** По `http://<IP компьютера>:8000` браузер не даёт GPS, установку и
  «Поделиться». Адрес trycloudflare меняется при каждом запуске туннеля.

## 4. Что недавно поменялось и почему — не откатывайте

**GPS в приложении (`webapp/app.html`)**
- Браузер даёт геолокацию только по HTTPS или на localhost. Приложение пишет «GPS недоступен:
  нужен HTTPS», а не «разрешите доступ» — пользователь не может это исправить разрешением.
- `?demo=1` включает демо-точку **только для текущей страницы** и ничего не сохраняет. Раньше
  превью в панели записывало демо в localStorage, и после этого настоящее приложение навсегда
  показывало демо-точку вместо GPS. Выбор пользователя хранится под ключом `sg.demoPoint`.
- Жалоба не отправляется, если точка вне района замеров или точность хуже 1 км (`COARSE_M`):
  такое место — это Wi-Fi/IP, а не GPS, квадрат 200 м по нему не определить.
- В CSS есть `[hidden]{display:none!important}`: без него `.btn{display:flex}` показывал
  скрытые кнопки. Не удаляйте.

**Плагин (`extension/`)**
- house.kg и lalafo.kg (React) примерно через секунду после загрузки **заменяют весь корневой
  блок страницы**, и плашка исчезала. `content.js` следит за этим (`MutationObserver`) и
  возвращает плашку под заголовок. Если плашка снова «пропадает» — проверьте сначала это.
- Точка **42.8746212, 74.5697617** — это «Бишкек по умолчанию» на lalafo для объявлений без
  адреса (~10 % объявлений). Она внутри нашего района, поэтому без фильтра плашка показывала
  связь чужого дома. Отбрасывается в **двух местах — держите их одинаковыми**:
  `PLACEHOLDERS` в `extension/extract.js` и в `server/listing.py`.

**«Поделиться» → Tolkun на телефоне (`server/listing.py`, `webapp/`)**
- Мобильный Chrome не поддерживает расширения, а объявления смотрят в приложениях house.kg и
  lalafo. Поэтому PWA встаёт в меню «Поделиться» Android (`share_target` в манифесте), а
  страницу объявления загружает сервер: `GET /api/listing?url=…` или `?text=…`.
- Безопасность: сервер ходит **только** на house.kg / lalafo.kg (и `m.`, `www.`), каждый
  редирект проверяется тем же списком — иначе через нас можно ходить на любые адреса (SSRF).
  Таймаут 8 с, страница до 5 МБ, не больше 3 редиректов, 20 проверок в минуту с IP.
- Кеш 10 минут; ошибки сайта (`502`) не кешируются.
- house.kg на снятое объявление отвечает **редиректом на главную**, а не 404 — сервер считает
  это «объявление не найдено».
- Если поменяете разбор страниц в `extract.js`, поменяйте и `server/listing.py` — логика одна.

**«Отправить сигнал» и карта квартир (`/api/reports`, `/api/listings`)**
- В плагине рядом с «Здесь нет связи» — «Отправить сигнал»: житель выбирает «Отлично / Нормально /
  Плохо / Нет связи» и сеть, если знает. Это **оценка жителя, а не замер**: расширение не видит
  сигнал телефона, а скорость интернета компьютера к дому из объявления отношения не имеет.
- Отметки — `var/reports.jsonl`, тот же лимит 5 в минуту с IP и проверка района. В админке —
  вкладка «Сигналы» (сравнение с медианой квадрата) и слой «Сигналы жителей» на карте.
- Квартиры на карте приложения — это объявления, которые кто-то проверил через «Поделиться»
  или плагин (`var/listings.json`, до 500). Только публичные данные: ссылка, заголовок, точка,
  связь. Плагин регистрирует квартиру через `/api/listing?url=<адрес вкладки>` — сервер сам
  загружает страницу, поэтому подделать координаты квартиры нельзя.
- **Плагин сам определяет зону квартиры и шлёт её оператору.** Плашка — вывод по зоне карты для
  адреса из объявления: «Хорошая связь — зелёная зона», «Средняя связь — жёлтая зона», «Плохой
  интернет — дом в красной зоне» (с медианой дБм). Вне района — просто «Дом вне зоны замеров», без
  оценок и кнопок. При каждом открытии объявления плагин без кнопок вызывает `/api/listing?url=<адрес
  вкладки>`: квартира попадает к оператору во вкладку «Квартиры» и на карту (вне района — с пометкой
  «вне зоны», `in_area: false`). Это вывод по карте, а не замер в квартире: интернет компьютера
  смотрящего к дому из объявления отношения не имеет, поэтому плагин его не меряет.
- Жалобы и отметки принимаются по всему Бишкеку (рамка `BISHKEK` из `server/listing.py`);
  `GET /api/crowd` — оценка жителей в радиусе 300 м для приложения вне района.
- **Автозамер в приложении — без ввода руками.** Как только определилось место (GPS точнее 1 км),
  приложение само меряет задержку (`speed.cloudflare.com`, запасной — `/health`), берёт у браузера
  тип сети, его оценку (4G/3G) и скорость и шлёт `POST /api/measurements` с `method: "auto"`.
  Цвет: 4G и пинг до 150 мс — хорошо, 2G или больше 400 мс — плохо. Не отправляется: по Wi-Fi или
  кабелю (это не мобильная связь), с демо-точки, с неточным местом, повторно в пределах 100 м и 5 мин.
  **Уровень сигнала в дБм браузер сайтам не отдаёт** — ни на Android, ни на iPhone; автоматически его
  может мерить только нативное Android-приложение. Ручной ввод (палочки 0–4, дБм с экрана «Состояние
  SIM-карты») остался в свёрнутом блоке «Уточнить вручную» (`method: "manual"`). Лимит — 20 замеров
  в минуту с IP. Оператор видит всё во вкладке «Замеры» (автозамеры с пометкой «авто»).
- При неточном месте (по IP/Wi-Fi, точность хуже 1 км) приложение не показывает данные квадрата —
  раньше на ноутбуке с точностью ±249 км показывался случайный квадрат.
- Вне района экран «Связь здесь» показывает замеры жителей из `/api/crowd` (медиана дБм на кольце
  или итог по палочкам), а не тупик.
- Приложение открывается на экране «Карта»; ссылка «Поделиться» по-прежнему ведёт на экран объявления.


- Вкладка «Приложение» убрана намеренно — она путала. Вместе с ней удалены `/api/info` и
  превью в iframe; сервер отдаёт `X-Frame-Options: DENY`. Не возвращайте iframe приложения.
- Квадраты сетки полупрозрачные: константы `CELL_OPACITY` (0.45) и `PICKED_OPACITY` (0.6).

**APK (`android/`) — сигнал с модема автоматически**
- `MainActivity` открывает `https://tolkun.online/app/` во WebView и даёт странице мост
  `window.AndroidSignal.read()`: `{dbm, network, source}` или `{error: no_permission | no_sim |
  no_signal | no_telephony | failed}`. Сигнал берётся по порядку: подписка на изменения сигнала
  (`TelephonyCallback`, на Android 10–11 — `PhoneStateListener`; на многих телефонах
  `getSignalStrength()` пуст, пока нет подписки) → `getSignalStrength()` → `getAllCellInfo()`.
  Для 4G — RSRP, для 5G — SS-RSRP.
- Разрешения: **точную и приблизительную геолокацию просим вместе** — на Android 12+ запрос одной
  `ACCESS_FINE_LOCATION` система молча игнорирует (так и было: место не определялось, дБм не читался).
- Страница в APK открывается на «Связь здесь», показывает дБм с модема первым блоком и обновляет его
  каждые 2 с без GPS и кнопок; ручной ввод спрятан. Замер уходит оператору как `method: "modem"`
  («с модема» во вкладке «Замеры»).
- Подпись: постоянный отладочный ключ `android/debug.keystore` (пароль `android`) — иначе каждая
  сборка GitHub подписывала APK новым ключом и обновление не ставилось поверх («Приложение не
  установлено»). Перед первой установкой этой версии старую нужно один раз удалить.
- Готовый APK — артефакт сборки GitHub `signalkg-meter-apk`; положить его в `webapp/tolkun.apk`.
  Страница берётся с боевого сайта, поэтому правки `webapp/` работают в APK только после деплоя.

**Сгенерированные файлы (`out/`)**
- `main.py` при каждом запуске меняет в `out/report.json` только время работы алгоритмов (`ms`).
  Не коммитьте этот шум: `git checkout -- out/report.json`.
- Поменяли `covermap/template.html` — перегенерируйте и закоммитьте `out/map.html`.
- `out/result.json` обязан совпадать с `data/07_coverage/expected.json` — это ответ жюри.

## 5. Как работать с git

- Новую работу делайте в ветке, `main` — то, что увидит команда.
- Перед коммитом: оба набора тестов зелёные, `out/result.json` не изменился.
- Сообщения коммитов — по-русски, как в истории: первая строка — что сделано, ниже — зачем.
- Не коммитьте: `.venv/`, `var/` (жалобы), `.playwright-mcp/`, ключи и токены (`DGIS_KEY`).
- В `var/complaints.jsonl`, `var/reports.jsonl` и `var/listings.json` могут остаться тестовые данные — очистите перед показом жюри.

## 6. Известные ограничения (можно брать в работу)

- **Лимит жалоб за туннелем общий.** За cloudflared все телефоны приходят с `127.0.0.1`, поэтому
  5 жалоб в минуту делятся на всех. Сервер намеренно не доверяет `X-Forwarded-For`; если
  чинить — доверять `CF-Connecting-IP` только когда соединение пришло с `127.0.0.1`.
- **На iPhone нет «Поделиться» для веб-приложений.** Нужен вариант «вставить ссылку» в
  приложении — серверная часть (`/api/listing?text=`) уже готова.
- **Нет постоянного HTTPS-адреса** — нужен хостинг или именованный туннель со своим доменом.
- Плагин проверен на живых house.kg и lalafo.kg 21.11.2026. Если сайты поменяют разметку,
  первым сломается `extractCoords` — проверяйте на реальном объявлении, а не только тестами.
